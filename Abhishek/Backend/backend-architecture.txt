3. HOW THE BACKEND WORKS (STEP-BY-STEP WORKFLOW)
--------------------------------------------------------------------------------

Step 1: Application Launch
- `server.ts` connects to MongoDB Atlas using `config/db.ts`.
- `server.ts` starts Express server on configured port and attaches Socket.IO.

Step 2: Incoming Request & Security Check
- Client sends HTTP request (e.g., PUT /api/tasks/123 to update task status).
- Request passes through `middleware/authMiddleware.ts` to verify JWT access token.
- `middleware/xssSanitizer.ts` ensures no malicious payload enters the application.

Step 3: Route & Controller Handling
- Request hits `routes/taskRoutes.ts`, which forwards it to `controllers/taskController.ts`.
- Controller extracts task ID, user permissions, and updated fields.

Step 4: Business Logic & Audit Trail
- Controller calls `services/taskService.ts` to execute business rules.
- Service updates `models/Task.ts` in MongoDB.
- Service creates a new record in `models/TaskAuditLog.ts` for immutable tracking.

Step 5: Real-Time Synchronization & Response
- `realtime/event.publisher.ts` emits a Socket.IO event to all assigned team members.
- Client receives instant 200 OK JSON response.
- Connected Web and Mobile apps reflect the updated status immediately.
